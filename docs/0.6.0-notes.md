# ZawkMapper 0.6.0 notes

This stable release includes improvements based on release candidate testing and developer feedback.

## Runtime map and projection are separate

`MapModel` and `ProjectModel` are now handled as separate registration types.

This was changed because real projects often need different rules for runtime mapping and database projection.

Runtime mapping may use normal C# methods, formatting, and conversions.

Projection should stay friendly for EF Core and SQL providers.

## Better messages and hover help

Public APIs now have clearer XML documentation so method hover text explains the source type, destination type, and common usage.

Duplicate registration messages now explain whether the duplicate is a runtime map or a projection.

## MVC sample additions

The MVC CRUD sample now includes pages for:

1. English and Sindhi named projection
2. Runtime `MapModel` and SQL-friendly `ProjectModel` for the same source and DTO
3. Salary increment using scenario-level configuration
4. Prefix and suffix using scenario-level configuration
5. Static cached configuration call using `AppMappingConfig.StaticConfigMethod()`

## Performance note

The performance lab includes new checks for runtime plus projection on the same pair, named Sindhi projection, and scenario-level salary increment projection.

Compare the new report with the 0.5.0-rc.4 report before publishing.
