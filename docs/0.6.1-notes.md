# ZawkMapper 0.6.1 Stable Release Notes

ZawkMapper 0.6.1 is the stable release of the tested 0.6.1 release candidate.

This version focuses on runtime object mapping performance, allocation reduction, stable EF Core `ProjectAs` projection behavior, and clearer public documentation for real-world .NET DTO mapping projects.

## Highlights

- fast .NET object mapper APIs with `MapModel`
- SQL-friendly EF Core IQueryable projection with `ProjectModel` and `ProjectAs`
- clear mapping modes with `MapField`, `MapFieldStrict`, and `MapFieldDirect`
- improved runtime mapping paths for common same-type and direct mapping scenarios
- lower allocation in common runtime mapping paths
- preserved projection behavior for EF Core and LINQ providers
- clearer docs for nested object mapping and collection mapping
- SEO-friendly package metadata for NuGet discoverability

## Performance position

ZawkMapper 0.6.1 was tested against Manual Mapping and AutoMapper in a public benchmark project.

The benchmark covers:

1. runtime flat DTO mapping
2. runtime summary DTO mapping
3. runtime nested object and collection mapping
4. cumulative runtime mapping
5. EF Core IQueryable projection
6. `ProjectAs` vs `ProjectTo` vs manual `Select`
7. time, memory, per-record cost, and checksum validation

Benchmark repository:

```text
https://github.com/zameer-hussain/ZawkMapper.Benchmarks
```

## Honest guidance

Manual mapping remains the best baseline for hand-written runtime speed.

ZawkMapper is competitive in flat DTO and summary DTO runtime mapping scenarios and provides strong EF Core `ProjectAs` projection performance.

Nested runtime collection mapping remains a future optimization target.

## Upgrade

```bash
dotnet add package ZawkMapper --version 0.6.1
```

## Recommended usage

Use `MapFieldStrict` when source and destination member types match.

Use `MapFieldDirect` for explicit direct assignment.

Use `MapField` for flexible conversion, computed fields, nested object mapping, and collection bridges.
